# Pinned deliberately -- see the note below before loosening anything.
#
# Streamlit Community Cloud re-resolves this file on EVERY reboot. With
# unpinned versions that means a reboot can silently move the running app
# to different library versions, which is how this app went from working
# Okta sign-in to a crashing one without a single line of code changing.
#
# streamlit is pinned exactly because two reported upstream bugs affect
# st.login(), both of which match the failures seen on this app:
#   * 1.57.0 introduced an "Invalid code verifier" failure during the
#     OAuth token exchange (streamlit/streamlit#15115). Reporters fixed it
#     by downgrading to 1.56.0 -- which is why that is the version here.
#   * Later versions on Python 3.14 have been reported to leave some OIDC
#     users stuck on a loading screen (streamlit/streamlit#16569).
# The [auth] extra is the documented way to install Authlib at a version
# Streamlit itself considers compatible, rather than pinning Authlib
# separately and guessing.
streamlit[auth]==1.56.0

# Left unpinned on purpose. None of these is implicated in the auth
# failure, and pinning them to versions nobody has verified against this
# deployment would trade a known problem for an unknown one. Pinning them
# properly needs a lockfile captured from a deploy that is confirmed
# working -- worth doing, but as a separate deliberate step.
anthropic[bedrock]
pymupdf
openpyxl
pillow
turso_serverless
